# LAST ONE STANDING 🪂

현재 버전: **v0.9.0-rc.6 · 프리릴리스**

**LAST ONE STANDING**은 참가자 명단을 넣으면 배틀로얄 관전 화면처럼 최후의 1인을 가려내는 웹 기반 랜덤 추첨기입니다.

핀볼이나 룰렛으로 이름을 뽑는 대신, 맵 위에 참가자들이 낙하하고 자기장이 좁혀지며 한 명씩 탈락하는 과정을 지켜본 끝에 우승자가 결정됩니다. 결과는 시작하는 순간 결과 전용 난수로 확정되며, 화면에 펼쳐지는 교전과 자기장은 별도의 연출 난수를 사용하는 순수한 연출입니다.

설치 없이 브라우저에서 실행되고, 전체 순위 복사·시드 재현·모바일 화면을 지원합니다.

> 이 프로젝트는 게임이 아니라 **추첨 도구**입니다. 배틀그라운드의 관전 문법을 빌려 “누가 뽑혔는가”라는 결과에 서사와 볼거리를 입히는 것이 목표입니다.

> **프리릴리스 안내:** 현재 버전은 사내 공개 전 점검 단계입니다. 정식 v1.0.0으로 확정하지 않았습니다.

## 🎯 왜 만들었나

사내에서 경품이나 순번을 정할 때 흔히 쓰는 룰렛·핀볼 추첨기는 결과가 나오기까지의 과정이 단조롭고, 여러 명 중 한 명을 뽑는 상황에서 긴장감이나 지켜보는 재미가 크지 않았습니다.

PUBG e스포츠 중계의 관전 미니맵을 보다가, **점들이 맵 위에서 움직이고 자기장이 좁혀지며 최후의 1인이 남는 그 화면 자체가 훌륭한 추첨 연출**이 될 수 있겠다는 데서 출발했습니다.

- 여러 명 중 한 명을 뽑는 과정을 지켜보는 재미가 있으면 좋겠다.
- 그러면서도 결과는 공정하고, 나중에 같은 조건으로 검증할 수 있어야 한다.
- 특정인에게 유리하지 않게, 이름이 여러 번 들어가면 그만큼만 확률이 오르게 하고 싶다.
- 결과를 팀 채널에 바로 공유할 수 있어야 한다.
- 설치나 서버 없이, 링크나 파일 하나로 누구나 열 수 있어야 한다.

### 해결하고 싶었던 문제

1. 단순한 이름 추첨을 배틀로얄 관전 화면처럼 **지켜보는 이벤트**로 만든다.
2. 연출이 아무리 화려해도 결과는 **시작 순간 확정된 결과 전용 난수**로만 정해지게 한다.
3. 같은 이름을 여러 번 넣으면 **딱 그 횟수만큼만** 당첨 확률이 오르게 한다.
4. 최종 순위를 텍스트로 **복사해 공유**하고, 시드로 **같은 순위를 재현**한다.

## 🧠 핵심 기능

| 기능 | 설명 |
|---|---|
| **명단 입력** | 쉼표나 줄바꿈으로 참가자를 구분합니다. `이름*3`처럼 쓰면 그 이름이 3장의 티켓으로 참가합니다. |
| **참가자·티켓 분리 표시** | 고유 참가자 수와 실제 추첨에 들어가는 티켓 수를 각각 표시합니다. |
| **공정한 결과 확정** | 시작하는 순간 결과 전용 난수로 전체 티켓 순서를 Fisher–Yates 셔플합니다. 이후 화면은 그 결과를 재생하는 연출입니다. |
| **결과·연출 난수 분리** | 순위를 정하는 난수와 낙하·자기장·교전에 쓰는 난수를 분리했습니다. 연출 코드를 바꾸더라도 결과 난수열을 소비하지 않습니다. |
| **자기장 연출** | 흰 원이 나타난 뒤 파란 자기장이 그 원까지 좁혀 들어옵니다. 6단계에 걸쳐 점점 작아집니다. |
| **분산 이동** | 참가자마다 다음 안전지대 안의 서로 다른 목표 지점을 정합니다. 모두가 원 중심 한 점으로 빨려 들어가는 대신, 이동과 대기를 반복하며 원 안 여러 위치에 자리 잡습니다. |
| **후반 카메라 확대** | 생존자가 20명 이하로 줄면 자기장과 남은 참가자를 중심으로 관전 카메라가 부드럽게 확대됩니다. 최후의 4인 구간에서는 작은 원과 참가자가 화면을 크게 차지합니다. |
| **교전·자기장 탈락 구분** | 교전 탈락은 `재범님 KILLS 태훈님`, 자기장 탈락은 `BLUE ZONE ELIMINATES 태훈님`처럼 표시하고 효과 색상도 주황·파랑으로 구분합니다. |
| **에란겔 맵 배경** | 실제 전장 지도를 화면 가득 표시하고, 참가자들이 도시 지역에 뭉쳐 낙하합니다. 화면 비율에 따라 지도의 가장자리는 일부 잘릴 수 있습니다. |
| **속도 조절** | 0.5배에서 3배까지 조절합니다. 진행 중 속도를 바꾸어도 게임 시간이 앞뒤로 순간이동하지 않습니다. |
| **고정 페이싱** | 인원과 관계없이 1배속 기준 약 60초, 기본 2배속 기준 약 30초에 끝납니다. |
| **전체 순위** | 모든 탈락 기록이 순위와 함께 남습니다. 같은 이름이 여러 번 참가한 경우 순위에 같은 이름이 여러 번 등장할 수 있지만, 화면에는 이름만 표시합니다. |
| **순위 복사** | 최종 순위를 앱 버전·알고리즘 버전·시드·명단 해시와 함께 복사합니다. |
| **시드 재현** | 같은 앱·알고리즘 버전, 같은 명단과 입력 순서에서 같은 시드를 넣으면 동일한 순위를 재현합니다. |
| **화면을 채우는 전장** | 데스크톱에서는 설정 패널을 제외한 공간을 전장이 가득 채웁니다. 작은 화면에서는 전장을 충분한 높이로 표시하고 탈락 기록과 설정을 아래에 배치합니다. |
| **입력 검증** | 빈 이름, 잘못된 티켓 형식, 한 명뿐인 명단, 잘못된 시드, 100장을 넘는 티켓을 시작 전에 안내합니다. |

## ⚖️ 공정성 — 이 도구의 척추

추첨 도구에서 가장 중요한 것은 화면이 아니라 **결과를 신뢰할 수 있는가**입니다. 이 프로젝트는 처음부터 다음 원칙 위에 세워졌습니다.

### 결과 확정과 연출의 분리

시작 버튼을 누르는 순간, 결과 전용 난수 생성기로 참가 티켓 전체를 **Fisher–Yates 셔플**해 탈락 순서를 완전히 확정합니다.

그 뒤에 펼쳐지는 낙하 위치·자기장·이동·교전은 결과 난수와 분리된 별도의 연출 난수를 사용합니다. 따라서 연출 과정에서 난수를 몇 번 더 사용하더라도 이미 확정된 순위는 바뀌지 않습니다.

즉, 자기장 밖에 있어서 탈락하는 것처럼 보이거나 교전에서 밀려 사라지는 것처럼 보여도, 그 순서는 화면이 그려지기 전에 이미 결정되어 있습니다.

### 티켓은 완전 평등

`이름*3`은 하나의 참가자에게 임의 보너스를 주는 방식이 아니라 **서로 독립된 3장의 티켓**입니다. 티켓 하나하나는 다른 모든 티켓과 동일한 당첨 확률을 가지며, 같은 이름의 티켓이라고 서로 뭉치거나 유리해지지 않습니다.

화면과 결과에서는 고유 참가자 수와 전체 티켓 수를 구분해 표시합니다. 같은 이름이 여러 번 참가하면 전체 순위에도 같은 이름이 여러 번 등장할 수 있지만, 각 항목에 별도의 번호를 붙이지 않고 이름만 보여줍니다.

### 시드와 재현 조건

시드를 다시 입력하면 같은 순위를 재현할 수 있습니다. 단, 정확한 검증을 위해서는 다음 조건이 같아야 합니다.

- 앱 버전
- 추첨 알고리즘 버전
- 참가자 명단
- 명단의 입력 순서
- 각 참가자의 티켓 수
- 시드

복사 결과에는 이를 확인할 수 있도록 다음 정보가 함께 기록됩니다.

- `app`
- `algorithm`
- `seed`
- `roster-hash`
- 참가자 수
- 티켓 수

**최종 순위는 위 조건에서 동일하게 재현됩니다.** 맵 위의 정확한 위치와 배치는 화면 크기에 따라 달라질 수 있습니다.

### 랜덤 시드 생성

시드 입력칸을 비우고 시작하면 브라우저의 Web Crypto API를 우선 사용해 32비트 시드를 만듭니다. 자동으로 생성된 시드는 입력칸을 채우지 않고, 실행 화면의 `seed` 표시와 복사 결과에만 기록됩니다. 따라서 입력칸이 빈 상태라면 다음 판도 자동으로 새로운 랜덤 시드로 시작합니다. 특정 시드를 직접 입력하면 그 값을 그대로 사용하며, 입력값은 사용자가 지우기 전까지 유지됩니다.

## 🌱 개발 과정 — 비개발자가 AI와 함께 만들기까지

이 프로젝트는 코드를 직접 작성하는 개발자가 아니라, **아이디어와 판단 기준을 가진 기획자가 AI에게 요구사항을 설명하고, 나온 결과를 실제로 돌려보며 반복해서 다듬는 방식**으로 만들어졌습니다. 아래는 그 과정을 단계별로 정리한 기록입니다.

### 1단계 — 컨셉을 한 문장으로 고정하기

가장 먼저 한 일은 기능 목록을 나열하는 것이 아니라, 이 도구가 **무엇이고 무엇이 아닌지**를 분명히 하는 것이었습니다.

- 이것은 게임이 아니라 추첨 도구다.
- 배틀그라운드의 관전 화면 문법을 빌리되, 목적은 어디까지나 “공정한 결과에 볼거리를 입히는 것”이다.
- 그러므로 화면 연출은 결과에 절대 영향을 주면 안 된다.

이 한 문장이 이후 모든 결정의 기준이 되었습니다. 새 기능을 추가할지 말지 고민될 때마다 “이게 결과의 공정성을 해치는가?”를 먼저 물었습니다.

### 2단계 — 공정성 구조를 먼저 설계하기

연출보다 공정성 구조를 먼저 확정했습니다. “시작 순간 Fisher–Yates 셔플로 순서를 확정하고, 나머지는 연출”이라는 뼈대를 세운 뒤 그 위에 화면을 얹는 순서로 진행했습니다.

특히 `이름*N` 입력이 독립 티켓으로 동작하는지 확인하기 위해, 같은 조건으로 추첨을 반복하는 시뮬레이션을 돌려 각 티켓의 당첨 비율이 이론값과 일치하는지 확인했습니다. 이 단계에서 “화면이 그럴듯해 보이는 것”과 “실제로 공정한 것”은 별개라는 점을 분명히 했습니다.

프리릴리스에서는 이 구조를 한 단계 더 강화해, **순위를 정하는 결과 난수와 화면을 만드는 연출 난수를 별도의 스트림으로 분리**했습니다.

### 3단계 — 맵과 낙하: 분위기 만들기

절차적으로 그린 격자 배경으로 시작했지만, 실제 관전 화면의 느낌을 내기 위해 **에란겔 지도 이미지를 배경으로 삽입**했습니다. 현재는 1008×1008 WebP 지도를 원본 디테일을 유지한 채 HTML 안에 직접 내장하고, 지도 자체를 강하게 재압축하거나 어둡게 저장하는 대신 실행 중 22% 검정 오버레이를 별도로 덧씌웁니다. 덕분에 도로와 지형은 이전보다 선명하면서도 참가자·자기장·교전 효과가 묻히지 않습니다. 프리릴리스 검토 과정에서 정사각형 전장도 시험했지만, PC 전체 화면에서 여백이 크게 생겨 관전 화면의 몰입감이 떨어졌습니다. 현재는 원본처럼 가용 영역을 전장이 채우고, 정사각형 지도는 가운데를 기준으로 일부 크롭됩니다.

참가자들이 맵 곳곳에 완전히 균등하게 흩어져 떨어지는 대신, 실제 게임처럼 **도시 지역에 뭉쳐 낙하**하도록 했습니다. 이 낙하 위치는 연출 전용 난수에서 만들어지며 결과와 무관합니다.

### 4단계 — 자기장: 가장 많이 다듬은 부분

자기장은 이 프로젝트에서 가장 여러 번 고쳐 잡은 요소입니다. 실제 배틀그라운드의 자기장 데이터를 참고 자료로 놓고 논의하며 다음을 조정했습니다.

- **첫 원의 크기**: 파밍 단계가 없는 추첨 도구 특성상 첫 자기장부터 어느 정도 압박이 있도록 크기를 잡았습니다.
- **수축률**: 처음에는 매 단계 50%씩 줄였지만 너무 급하게 작아진다는 판단에 완화했고, 마지막 원이 하한에 걸려 더 이상 줄지 않는 문제를 해결하기 위해 **첫 원과 마지막 원을 고정하고 그 사이를 일정 비율로 나누는 방식**으로 최종 결정했습니다.
- **이동 속도 곡선**: 실제 게임처럼 초반 자기장은 빠르게 닫히고 후반으로 갈수록 느리게 기어오도록 단계별 시간을 다르게 설정했습니다.
- **후반 위험 신호**: 후반에는 자기장 밖에 남은 점이 푸르게 점멸하고, 자기장 탈락은 파란 섬광과 별도 킬로그로 표시해 위험 원인을 바로 알아볼 수 있게 했습니다.

이 과정에서 실제 게임 데이터 중 **추첨 도구에 필요한 것만 취하고, 불필요한 것은 버리는** 판단을 반복했습니다.

### 5단계 — 교전과 자기장 탈락: 화면을 살아 있게

탈락을 단순히 점이 사라지는 것으로 두지 않고, **탈락 예정자가 가까운 상대와 대치하다 사라지는 교전 연출**을 넣었습니다. 탈락과 무관한 생존자도 근처에서 비살상 교전과 넉백·섬광을 벌이도록 해 필드가 활발해 보이도록 만들었습니다.

실제 관전 화면을 다시 대조하면서 탈락 원인도 나눴습니다. 안전지대 안에서 발생하는 탈락은 가까운 참가자가 처치한 것으로 연출하고 `재범님 KILLS 태훈님`처럼 표시합니다. 자기장 경계에 걸린 참가자는 상대 없이 파란 효과에 휩싸여 사라지고 `BLUE ZONE ELIMINATES 태훈님`으로 기록됩니다. 최후의 1대1은 교전으로 마무리해 결승 구간의 긴장감을 유지합니다.

같은 이름이 여러 장의 티켓으로 참가하더라도 `재범님 KILLS 재범님`처럼 자기 자신을 처치한 것처럼 보이지 않도록, 교전 상대는 가능한 한 다른 이름에서 선택합니다. 적절한 상대가 없으면 자기장 탈락 연출로 전환합니다.

교전과 자기장 탈락은 모두 이미 확정된 탈락 순서를 따라가는 연출일 뿐, 어느 원인으로 보이느냐가 결과를 만들지는 않습니다.

### 6단계 — 페이싱: 얼마나 오래 지켜볼 것인가

한 판이 인원 수와 관계없이 일정한 시간에 끝나도록 **총 길이를 고정**했습니다. 초반 45초 동안 대부분이 점진적으로 탈락하고, 마지막 15초는 최후의 몇 명이 대치하도록 배분했습니다. 판마다 조금씩 달라 보이도록 연출용 무작위 변주를 넣되, 최후 대치 구간은 안정적으로 유지했습니다.

기본 속도는 2배로, 한 판이 약 30초에 끝납니다. 슬라이더로 더 느긋하게 0.5배 또는 더 빠르게 3배까지 바꿀 수 있습니다.

프리릴리스에서는 게임 시간을 실제 프레임 수에 직접 묶지 않고 **고정 시뮬레이션 스텝으로 누적**하도록 고쳤습니다. 덕분에 모니터 주사율이나 진행 중 속도 변경 때문에 시간이 갑자기 앞으로 또는 뒤로 이동하지 않습니다.

### 7단계 — 결과 공유: 도구를 실용적으로

연출이 끝나면 우승자만 크게 보이고 그 앞의 순위는 확인할 수 없는 문제가 있었습니다. 이를 해결하기 위해:

- 전원의 순위를 끝까지 보존하고 스크롤되게 했습니다.
- 우승 화면에 **전체 순위 보기**와 **순위 복사** 버튼을 추가했습니다.
- 같은 이름이 여러 번 참가해도 개별 번호를 붙이지 않고 이름만 표시합니다.
- 복사 결과에 시드뿐 아니라 앱 버전·알고리즘 버전·명단 해시를 함께 기록합니다.

### 8단계 — 시드 입력: 재현 가능성 완성

사용자가 직접 시드를 입력하는 칸을 추가했습니다. 특정 시드를 넣으면 같은 앱과 알고리즘 버전, 같은 명단과 입력 순서에서 같은 전체 순위가 재현됩니다.

프리릴리스에서는 잘못된 시드를 조용히 무시하고 랜덤으로 바꾸지 않도록 수정했습니다. 시드는 1~8자리 16진수만 허용하며, 잘못 입력하면 시작 전에 안내합니다.

### 9단계 — 모바일 반응형: 실사용 환경 대응

처음에는 가로로 넓은 데스크톱 화면을 전제로 만들어, 세로로 긴 휴대폰에서는 맵이 거의 보이지 않았습니다. 이를 해결하기 위해:

- 데스크톱에서는 설정 패널을 제외한 가용 영역을 전장이 가득 채웁니다. 화면 비율에 따라 에란겔 지도의 가장자리는 일부 잘릴 수 있습니다.
- 맵을 가리던 탈락 기록은 **맵 아래 별도 영역**으로 내립니다.
- 명단·설정·공정성 정보는 그 아래에 배치합니다.
- 버튼과 입력 요소를 손가락으로 다루기 좋게 유지합니다.
- 진행 중 화면 크기나 방향이 바뀌면 플레이어와 자기장 좌표를 새 크기에 맞게 조정합니다.

데스크톱에서는 왼쪽 설정 패널을 제외한 나머지 화면을 전장이 채웁니다. 좁은 화면에서는 맵, 탈락 기록, 설정 패널 순서의 세로 구조로 바뀝니다.

### 10단계 — 프리릴리스 점검

v1.0.0을 확정하기 전에 다음을 추가로 정리했습니다.

- 결과 난수와 연출 난수 분리

- 고정 시간 스텝과 안전한 속도 변경
- 참가자 수와 티켓 수 분리 표시
- 빈 이름·한 명뿐인 명단·100장 초과·잘못된 시드 검증
- 앱 버전·알고리즘 버전·명단 해시 기록

### 11단계 — 실제 관전 미니맵과 다시 대조하기

PNC 관전 화면을 직접 찍은 사진과 현재 앱을 나란히 보며, 단순히 파란 원과 이름표가 있다는 수준을 넘어 **관전 화면의 흐름이 닮았는지**를 확인했습니다.

- 초반에는 넓은 전장을 보여주고, 후반에는 자기장 주변을 확대한다.
- 참가자는 모두 중앙으로 모이지 않고 안전지대 안 여러 위치에 분산된다.
- 교전 탈락과 자기장 탈락은 킬로그와 효과만 봐도 구분된다.
- 구현하지 않는 별도 폭격 위험 지역의 단계 문구와 관련 흔적은 제거한다.

이 대조를 바탕으로 생존자가 20명 이하가 되면 카메라가 서서히 자기장으로 접근하고, 참가자마다 다음 원 안의 개별 목표 지점을 갖도록 이동 로직을 바꿨습니다. 또한 킬로그를 `KILLS`와 `BLUE ZONE ELIMINATES`로 나누고, 자기장 탈락에는 파란 점멸과 섬광을 사용했습니다. 낙하산 조작·파밍·무기 능력치는 여전히 구현하지 않았습니다. 그것들은 추첨 결과를 보여주는 데 필요하지 않고, 한 판을 빠르게 관전한다는 목적을 흐릴 수 있기 때문입니다.

### 이 과정에서 배운 것

- **먼저 컨셉과 원칙을 문장으로 고정하면**, 이후 수많은 선택에서 흔들리지 않는다.
- 화면이 그럴듯해 보이는 것과 실제로 옳게 동작하는 것은 다르므로 **숫자와 반복 실행으로 검증**해야 한다.
- 결과와 연출을 말로만 구분하는 것이 아니라 **코드의 난수 스트림까지 분리**해야 유지보수 중에도 원칙이 보존된다.
- 실제 참고 자료에서 **목적에 맞는 것만 취하고 나머지는 버리는 판단**이 중요하다.
- 좋은 결과는 한 번에 나오지 않는다. **돌려보고, 어색한 지점을 말로 짚고, 다시 고치는 반복**이 핵심이다.
- 비개발자도 “무엇을·왜” 원하는지 분명히 설명하고 결과를 판단할 수 있다면, AI를 도구 삼아 완성된 산출물을 만들 수 있다.

## 🕹️ 사용 방법

### 기본 흐름

1. 명단 입력칸에 참가자를 쉼표나 줄바꿈으로 구분해 적습니다.
2. 여러 티켓을 주려면 `이름*3`처럼 씁니다.
3. 참가자와 티켓 수, 입력 오류 안내를 확인합니다.
4. 선택적으로 속도와 시드를 설정합니다. 시드를 비우면 새 랜덤 시드를 생성합니다.
5. **시작**을 누르면 낙하 → 자기장 수축과 분산 이동 → 교전·자기장 탈락 → 최후의 1인 순서로 진행됩니다.
6. 끝나면 우승자가 표시됩니다. **전체 순위 보기**로 결과를 확인하고, **순위 복사**로 공유합니다.

### 입력 조건

- 서로 다른 참가자가 최소 2명 필요합니다.
- 티켓은 최소 2장, 최대 100장입니다.
- 이름은 40자 이하입니다.
- `이름*N`의 N은 1 이상의 정수입니다.
- 시드는 비워 두거나 1~8자리 16진수로 입력합니다.

### 명단 입력 예시

```text
공주님, 일원님*5, 재범님*5, 하빈님*3, 병식님, 정환님
```

- 쉼표 또는 줄바꿈으로 구분합니다.
- `일원님*5`는 일원님이 5장의 독립 티켓으로 참가한다는 의미입니다.
- 화면에는 `참가자 6명 · 티켓 16장`처럼 각각 표시됩니다.

### 결과 복사 형식

```text
LAST ONE STANDING 결과
app: v0.9.0-rc.6
algorithm: los-shuffle-v2
seed: b4357198
roster-hash: 91d4a1c2
참가자: 6명
티켓: 16장

전체 순위
1위: 재범님
2위: 일원님
3위: 하빈님
...
```

같은 앱·알고리즘 버전, 같은 명단과 입력 순서에서 위 시드를 다시 입력하면 동일한 전체 순위를 재현합니다.

## ⚙️ 어떻게 동작하나 — 비개발자 설명

### 단일 HTML 웹앱

화면 디자인, 추첨 로직, 맵 이미지, 애니메이션이 모두 `index.html` 파일 하나에 들어 있습니다. 별도의 설치나 서버 없이 브라우저에서 열면 바로 실행되며, 파일을 내려받아 직접 열어도 동작합니다.

### 결과를 먼저 정하고, 그다음 그린다

시작하는 순간 결과 전용 난수로 전체 순위를 확정합니다. 화면에 그려지는 자기장과 교전은 그 확정된 순서를 시간에 맞춰 재생할 뿐입니다.

### 하나의 시드, 세 개의 난수 흐름

사용자가 보는 시드는 하나지만 내부에서는 용도에 따라 별도의 난수 흐름을 만듭니다.

1. **결과 난수** — 전체 순위를 결정
2. **배치 난수** — 낙하 위치, 자기장 경로, 탈락 시간의 연출 변주
3. **이동 난수** — 움직임, 비살상 교전, 섬광 등 실시간 연출

결과 난수는 연출 난수와 분리되어 있으므로 연출 개선이 순위를 바꾸지 않습니다.

### 고정 시간 스텝

애니메이션은 모니터가 한 초에 몇 번 화면을 그리는지에 직접 의존하지 않습니다. 내부 게임 시간은 일정한 간격으로 누적되며, 속도 슬라이더는 그 시간의 진행 비율만 바꿉니다.

### 개별 이동 목표와 관전 카메라

각 참가자는 자기장 중심을 그대로 목적지로 삼지 않습니다. 다음 안전지대 안에서 서로 다른 목표 지점을 정하고, 잠시 대기한 뒤 다른 지점으로 이동합니다. 자기장 밖에 남으면 대기 시간을 취소하고 안전지대로 이동하지만, 원 안에서는 여러 위치에 흩어진 상태가 유지됩니다.

생존자가 20명 이하로 줄면 카메라는 현재 자기장과 생존자 무리의 중심을 함께 따라가며 서서히 확대됩니다. 지도만 확대하고 마커와 이름표 크기는 화면 기준으로 유지해, 후반에도 참가자 이름을 읽을 수 있도록 했습니다. 모션 감소 설정이 켜진 환경에서는 자동 확대를 적용하지 않습니다.

### 화면 크기에 맞춘 자동 조정

데스크톱에서는 왼쪽 설정 패널을 제외한 공간 전체를 전장으로 사용합니다. 에란겔 지도는 비율을 보존하면서 화면을 빈틈없이 채우므로, 화면 비율에 따라 지도 가장자리가 일부 잘릴 수 있습니다. 모바일에서는 맵, 탈락 기록, 설정 패널 순서로 세로 배치됩니다. 진행 중 창 크기나 방향이 바뀌어도 좌표를 새 화면에 맞춰 조정합니다.

### 로컬 처리

참가자 명단과 결과는 브라우저 안에서만 처리됩니다. 이 HTML 자체에는 명단을 외부 서버로 보내는 네트워크 요청이 없습니다.

## 🚀 실행과 배포

### 로컬에서 실행

1. `index.html`을 내려받습니다.
2. Chrome, Edge, Safari 등 브라우저로 파일을 엽니다.

### 저장소에서 실행

1. 저장소 최상위에 `index.html`과 `README.md`를 올립니다.
2. 저장소 페이지에서 `index.html`을 내려받아 실행하거나, Pages 기능을 켭니다.

### GitHub Pages로 배포

1. 저장소 최상위에 `index.html`과 `README.md`를 올립니다.
2. 저장소의 **Settings → Pages**로 이동합니다.
3. **Deploy from a branch**를 선택합니다.
4. `main` 브랜치와 `/(root)`를 선택해 저장합니다.
5. 생성된 Pages 주소로 접속합니다.

`index.html`이 저장소 루트의 기본 진입 파일이므로 별도의 파일명 변경이 필요하지 않습니다.

- 사용자가 직접 입력한 시드는 그대로 유지되고 같은 조건에서 다시 사용되는지
- 같은 시드와 명단으로 두 번 실행했을 때 전체 순위가 같은지
- 같은 시드와 명단을 데스크톱과 모바일에서 실행했을 때 순위가 같은지
- 데스크톱에서 전장이 가용 영역을 가득 채우는지
- 모바일에서 전장이 충분한 높이로 표시되고 기록과 설정이 아래에 배치되는지
- 에란겔 지도가 비율을 유지하면서 전장 영역을 빈틈없이 채우는지
- 생존자가 줄어들 때 카메라가 자기장 쪽으로 부드럽게 확대되는지
- 확대 중에도 마커와 이름표가 읽을 수 있는 크기를 유지하는지
- 참가자들이 한 점에만 몰리지 않고 다음 안전지대 안 여러 위치에 분산되는지
- 교전 킬로그의 `KILLS`와 자기장 킬로그의 `BLUE ZONE ELIMINATES`가 각각 표시되는지
- 같은 이름이 여러 장 참가해도 `이름 KILLS 같은 이름` 형태의 킬로그가 생성되지 않는지
- 구현하지 않는 별도 폭격 위험 지역의 단계 문구가 남아 있지 않은지
- 탈락 기록이 맵 아래, 입력 패널이 그 아래에 배치되는지
- 전체 순위가 모든 참가 항목을 보존하고 이름만 표시하는지
- 브라우저 오류 없이 한 판이 종료되는지

## 📝 변경 이력

### v0.9.0-rc.6 — 랜덤 시드 기본 동작 보정

### v0.9.0-rc.5 — 관전 미니맵 연출 개선

- 생존자 20명 이하부터 자기장과 생존자 무리를 따라가는 후반 카메라 확대 적용
- 최후의 4인 구간에서 작은 원과 참가자가 화면을 더 크게 차지하도록 조정
- 참가자마다 다음 안전지대 안의 개별 목표 지점을 부여해 원 중심 쏠림 완화
- 이동과 대기를 반복하도록 해 안전지대 안 여러 위치에 분산된 관전 화면 구성
- 교전 탈락을 `이름 KILLS 이름`, 자기장 탈락을 `BLUE ZONE ELIMINATES 이름`으로 구분
- 자기장 탈락에 파란 점멸·펄스·소멸 효과 적용
- 같은 이름끼리 자기 자신을 처치한 것처럼 보이는 킬로그가 생성되지 않도록 상대 선택 보완
- 실제로 구현하지 않는 별도 폭격 위험 지역의 단계 문구와 관련 흔적 제거
